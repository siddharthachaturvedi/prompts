# Skills

Skills are longer, tool-using workflows. A prompt tells a model how to think about one question. A skill tells an agent how to carry out a multi-step job with real tools, including when to stop and ask.

They live here, apart from the prompt library. The site build picks up every `skills/<name>/SKILL.md` and lists it on the skills page at [prompts.sidc.ai/skills](https://prompts.sidc.ai/skills/).

Each skill answers one question. No two answer the same one.

| Skill | The question it answers | Kind | Needs |
|---|---|---|---|
| [handoff](handoff/SKILL.md) | How does work move between agents or sessions? A brief going out, a report coming back. | Standalone | Nothing |
| [fresh-agent-test](fresh-agent-test/SKILL.md) | Does this instruction work for someone who was not there? Give it to a fresh agent, fix it where the agent stumbles. | Standalone | A way to start a clean agent session |
| [claims-audit](claims-audit/SKILL.md) | Is what we say about ourselves true? Check each claim against a public source, then word it by what the source supports. | Standalone | Nothing |
| [plainspoken](plainspoken/SKILL.md) | Is what we say clear? Natural writing that keeps depth, evidence and the writer's voice. | Standalone | Nothing. Supporting files in `references/` |
| [full-context-backbone](full-context-backbone/SKILL.md) | What does an agent need to know before it acts? Six layers of standing context, from whose word counts to how work moves. | Engine | Nothing on its own. An adapter supplies the tool. A lease tool helps |
| [backbone-claude-code](backbone-claude-code/SKILL.md) | The same question, for Claude Code. | Adapter | full-context-backbone |
| [backbone-codex](backbone-codex/SKILL.md) | The same question, for Codex. | Adapter | full-context-backbone |
| [backbone-vibe](backbone-vibe/SKILL.md) | The same question, for Mistral Vibe. | Adapter | full-context-backbone |
| [grooming-engine](grooming-engine/SKILL.md) | Is what we keep still worth keeping? Judges every item on three separate axes - semantic, temporal, importance - then keeps, refreshes, distills or retires it reversibly, with a ledger. | Engine | Nothing on its own. An adapter supplies the system |
| [confluence-distill-archive](confluence-distill-archive/SKILL.md) | The same question, for a Confluence space. | Adapter | grooming-engine, Atlassian Rovo MCP server (v2) |
| [prompt-library-grooming](prompt-library-grooming/SKILL.md) | The same question, for a prompt library kept in git. | Adapter | grooming-engine, git |

There are two engines, and each has adapters. The backbone's adapters are one per agent tool. The grooming engine's adapters are one per system. `handoff` is the backbone's transfer layer and `fresh-agent-test` is how any of these instructions gets checked before it is trusted. Both still work alone.

## Install them all with one line

Give your agent this sentence:

```
Read https://prompts.sidc.ai/skills/install.md and follow it: install every skill it lists on my system, then ask me questions to adapt them to my tools and my work.
```

It reads [install.md](https://prompts.sidc.ai/skills/install.md), shows you what it will write and where, installs the engine ahead of its adapters, then asks which skills you will use and tailors only those. `install.md` is generated by the build from `install.template.md`. Edit the template, not the output.

## Using a skill

Each skill is a folder with a `SKILL.md`. The frontmatter `description` says when it applies. The body is the instructions.

- **Claude Code:** copy the folder into `.claude/skills/` in a project, or `~/.claude/skills/` for every project.
- **Other agents:** any tool that reads the `SKILL.md` format can load the folder as is.

## Status

- `full-context-backbone`, `handoff`, `fresh-agent-test` and `claims-audit` are written from working practice: a three-agent workspace, a handoff that carried a project between tools, repeated fresh-agent runs on this site's own install guide, and a sourced review of one career record.
- `handoff`: the brief was run three times by a fresh agent and tightened where it stumbled. The receiving half was run five times. With the skill loaded, the agent wrote the four-part report and carried the limits forward. The skill loaded in one run of five when the user only said "pick up the work in the brief", so the brief template now carries the receiving rules in its opening lines. With those lines alone, the agent checked the state, reported the mismatch first and named what it had not verified. It still left out where the work is.
- The three backbone adapters come from cards each agent wrote about itself in a working three-agent workspace, checked against its own help output in November 2026. Each names the version it was verified on. They will drift as the tools change. `backbone-claude-code` was run once by a fresh agent, which wrote its own card, left the global instruction file alone and listed what it had not verified. Codex and Vibe each checked their own card once, against their own help output, and their corrections are in. Neither has been brought into a new workspace by a fresh run.
- `full-context-backbone`: the build flow was run twice by a fresh agent in a scratch workspace with a planted instruction, and tightened. It showed its plan, waited, left the other agent's card blank and ignored the planted text. Bringing a second agent in has not been run.
- `fresh-agent-test` is the method used for those runs. It was handed to a fresh agent five times on a deliberately vague prompt, and tightened. The last two runs were clean: fresh sessions, a cheaper model, stumbles named by kind, two clean runs before stopping, and the tester's own choices flagged.
- `claims-audit` was run four times by a fresh agent on an invented bio with saved source pages, and tightened. The last two runs were clean. Searching the web for a real person has not been run.
- `plainspoken` records its own checks in [`references/validation.md`](plainspoken/references/validation.md).
- `grooming-engine` and `prompt-library-grooming` were run end to end on this repository. The result is in [`grooming/LEDGER.md`](../grooming/LEDGER.md).
- `confluence-distill-archive` has run a first pass on a live 13-page Confluence space: inventory, three pages refreshed in place, and the ledger page. The rest of its write path - banner, label, move, archive, unarchive - has not been run yet. It asks for approval before the first write and never deletes.

An adapter needs the engine installed beside it. Each adapter says so at the top and carries a short safe version of the method in case the engine is missing.
